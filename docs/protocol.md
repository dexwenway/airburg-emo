# Airburg EMO 一代 协议说明

来源：原厂 `cn.airburg.emo` v2.0.0 的协议分析 + BLE 实机读取校验。

## 设备发现

- 广播名：`PM2.5TESTER`（实测确认，与原厂 `R.string.device_name` 的 contains 匹配一致）
- 传输：BLE GATT，无配对
- 设备无开关，上电即开始测量

## GATT 结构（实测）

| Service | Characteristic | 属性 | 用途 |
|---|---|---|---|
| `0000fff0-…` | `fff1` | read | 固定 `01`，疑似服务版本/状态 |
| | `fff2` | read | **实时测量帧** |
| | `fff3` | read/write | 采样间隔，read 返回 `0x0a`(10 分钟)；write `{10}` / `{60}` 切换间隔 |
| | `fff4` | notify | 连续监测历史数据通知通道 |
| | `fff5` | read/write | 历史传输状态；write `1` 触发传输，write `0` 关闭 |
| | `fff6` | read/write | write `1` 开始连续监测，write `0` 停止；read 为状态 |
| | `fff7` | read/write | write `0`/`1`，原厂用于语言/制式切换 |
| | `fff8` | read/write | write 5 字节设备时间，read 返回当前时间 |
| | `fff9` | read | 历史记录条数（u16 BE） |
| | `fffa` | read/write | 单字节状态，原厂回调用 |
| | `fffb` | read | 单字节状态 |
| | `fffc` | read/write | 读 `6168`（ASCII "ah"）；原厂写 `{96,72}` |
| | `fffd` | write | 写 1 字节索引，读取指定历史记录 |
| `0000180f-…` | `2a19` | read | 电池百分比 (u8) |

另有一个 TI 固件升级服务 `f000ffc0-0451-4000-b000-000000000000`（`ffc1`/`ffc2`），不使用。

## 实时帧 `fff2`

19 字节，大端多字段：

```
00 28 | 00 34 | 00 38 | 00 1e | 00 2b | 00 34 | 22 da | 07 a4 | 00 ed
  ^0      ^2      ^4      ^6      ^8      ^10     ^12     ^14     ^16
```

- `[10:12]` **PM2.5 原始值，u16 BE**，`µg/m³ = raw × 1.265`
- `[12:14]` **粒子数原始值，u16 BE**，`0.3µm 粒子数 / 0.1L = raw × 2.56`，负值归零
- `[0:10]` 六组 u16 BE，实测随读数联动，疑似 PM1.0/PM2.5/PM10 与 CF=1/大气环境两套值；UI 不使用
- `[14:19]` 尾部 5 字节，抽样看为 `07 a4 00 ed` / `08 44 00 cf` 等，疑似版本/校验/计数器，未使用

实测样本（2026-11-22 21:05，室内）：

| hex | PM2.5 |
|---|---|
| `0027003e0041001f0031003b000000000000` | 74.6 |
| `002800340038001e002b003422da07a400ed` | 65.8 |
| `002a0038003e001f002d0038255c08520120` | 70.8 |

原厂解析实现：取两字节 → 交换 → 按小端读，等价于直接按大端读。
注意：二代开源项目注释写「PM2.5 大端、粒子小端」是错的，一代与二代实际都是大端。

## 设备时间 `fff8`

写 5 字节：`{year-2000, month, day, hour, minute}`。
读回同样 5 字节。用于历史记录对齐。

## 连续监测（设备端历史）

原厂逻辑（主界面与历史模块）：

1. `fff8` 写当前时间
2. `fff6` 写 `1` 开始，设备每 10 分钟记一条（可 `fff3` 写 10/60 改间隔）
3. `fff6` 写 `0` 停止
4. `fff9` 读条数 N（最多 120 条 = 12 小时）
5. `fff5` 写 `1` 触发传输；`fff4` 收到通知帧
6. `fffd` 写索引 i 逐条取；或历史整包按每 2 字节一条、**大端 u16 × 1.265**

每条约 2 字节 PM2.5 原始值，时间由起始时间 + 序号 × 间隔推算。

## 电池

标准 BAS：service `0000180f`，char `00002a19`，u8 百分比。

## 与二代（emo plus）的差异

| 项 | 一代 EMO | 二代 emo plus |
|---|---|---|
| 广播名 | `PM2.5TESTER` | `PM2.5TESTER` |
| 实时数据 | `fff2` 19 字节，PM2.5 @10 | `fff2` ≥14 字节，PM2.5 @10 |
| 预热命令 | 无（上电即测） | 读 `fff3` 触发预热，等 ~20s |
| 历史 | `fff4`~`fff9`、`fffd` 整套 | 无公开实现 |
| 电池 | `2a19` | `2a19` |

## 原厂 APK 元数据（aapt2 实测）

- 包名 `cn.airburg.emo`，versionName 2.0.0 (versionCode 200)
- `minSdkVersion 18`，`targetSdkVersion 21`（Android 5.0）
- 权限只有 `BLUETOOTH` / `BLUETOOTH_ADMIN`

**无法在 Android 16 运行的根因**：Android 15（API 35）起系统拒绝安装 `targetSdk < 24` 的应用，Android 16 延续该限制。原厂 targetSdk 21 因此被系统直接拦截，与蓝牙本身无关。

## 原厂实现中的其他线索

- 原厂用 `BluetoothLeService` + `connectGatt(context, false, callback)`，未做 Android 12+ 权限适配。
- 原厂无前台服务，App 退到后台/黑屏后 BLE 会断，这正是新客户端要改掉的核心问题。
